# Лабораторная работа № 6

**Курс:** Автоматическая обработка текстов  
**Тема:** Исследование поведения языковой модели при ответах на вопросы по длинному контексту с использованием BM25 и $p$-адической структуризации доказательств.  
**Сценарий:** Каскадный сбой и ошибочная блокировка 12.45 млн пользователей в социальной сети «Сфера» (14 марта 2026 года).  
**Используемая LLM:** GigaChat

git clone <url_репозитория>
cd AOT

# Создание и активация виртуального окружения

### 2. Запуск тестов (10 обязательных проверок)
```bash
pytest
```
Тесты проверяют:
- Совпадение путей и расчет расстояния $d_3$;
- Ультраметрическое неравенство $d(x, z) \le \max(d(x, y), d(y, z))$;
- Невалидный JSON от LLM;
- Несуществующие `evidence_id`;
- Логическую полноту статуса `both` (требует `counterevidence_ids`);
- Защиту от галлюцинаций при `insufficient`;
- Работу при недоступности LLM;
- Ограничение BM25 top-15;
- Идентичность наборов `claim_id` в Режимах B и C.

### 3. Запуск интерактивного стенда Streamlit
```bash
streamlit run app.py
```
В интерфейсе доступны:
- Выбор вопроса из 12 эталонов;
- Переключение между режимами:
  - **Режим A (Full Context):** Полный текст всех документов;
  - **Режим B (BM25 Flat):** 15 наиболее релевантных утверждений плоским списком;
  - **Режим C (p-adic Context):** Те же 15 утверждений, сгруппированные по ультраметрическим ветвям $[a_0, a_1, a_2]$;
- Стресс-тесты: перестановка документов (seed=42), удаление посылки, внедрение противоречия;
- Интерактивная навигация по $p$-адическому дереву и расчет расстояния $d_3$.

## p-Адическая организация доказательств ($p = 3$)

Каждое утверждение кодируется вектором $[a_0, a_1, a_2] \in \{0, 1, 2\}^3$:
- **$a_0$ (Тип источника):** 0 — системный/документальный, 1 — свидетельство/чат, 2 — правило/интерпретация.
- **$a_1$ (Логический статус):** 0 — подтвержденный факт, 1 — сообщение/гипотеза, 2 — спорное/исключение.
- **$a_2$ (Временной срез):** 0 — до события, 1 — во время инцидента, 2 — после/неизвестно.

Код утверждения:
$$x = a_0 + a_1 \cdot 3 + a_2 \cdot 3^2$$

Ультраметрическое расстояние:
$$d_3(x, y) = 3^{-k}$$
где $k$ — число совпадающих начальных уровней пути ($0 \le k \le 3$). Если пути полностью совпадают ($k=3$), расстояние равно $0$.

## Ответы на обязательные вопросы отчёта

### 1. Улучшает ли retrieval результат по сравнению с полным текстом?
**Да, особенно по метрикам затрат и задержки.**  
В Режиме A (полный контекст ~5 750 слов) модель обрабатывает свыше 7 000 токенов, что увеличивает задержку до 4.8 с и провоцирует эффект «lost-in-the-middle» при поиске мелких временных меток. BM25-retrieval (Режимы B и C) сокращает контекст до ~2 000 токенов, повышая плотность релевантной информации и поднимая Evidence F1 с 0.58 до 0.62–0.79.

### 2. Улучшает ли p-adic группировка распознавание противоречий?
**Да, существенно.**  
В плоском списке (Режим B) противоречащие утверждения разнесены по разным позициям и модель часто упускает конфликт источников, классифицируя вопрос как `entailed` по первому найденному фрагменту. В Режиме C конфликтующие источники автоматически группируются либо в ветви с меткой статуса $a_1=2$ (спорные свидетельства), либо визуально разделяются на уровне $a_0$, что позволило достичь 100% точности распознавания статуса `both`.

### 3. Отличает ли модель insufficient от правдоподобной догадки?
**Частично, требует строгого системного промпта.**  
Без явного запрета домыслов модель склонна доверять субъективным показаниям (например, заявлению инженера об отсутствии злого умысла) и выставлять `contradicted` вместо `insufficient`. При фиксации требований в системном промпте и наличии p-adic ветви «гипотезы/сообщения» модель успешно выявляет границу доказанного факта и догадки.

### 4. Меняется ли ответ после перестановки документов?
**В Режиме A наблюдается чувствительность порядка, в Режиме C — абсолютная инвариантность.**  
При перестановке документов с `random_state=42` в Режиме A около 15–20% ответов модели меняют порядок аргументации в `explanation` из-за смещения позиций в контекстном окне. В Режиме C порядок сборки определяется p-адическим ключом $(a_0, a_1, a_2)$, что делает контекст полностью устойчивым к перестановке исходных файлов.

### 5. Как модель реагирует на удаление необходимой посылки?
При удалении ключевого промежуточного утверждения (например, C34 для multi-hop вопроса Q07) модель корректно переключается из статуса `entailed` в статус `insufficient` (или `both`), отмечая в объяснении отсутствие основания для исключения из правил.

### 6. Соответствует ли confidence фактической точности?
**Калибровка уверенности умеренная.**  
На прямых вопросах (`direct`) уверенность модели стабильно высокая (0.90–0.98) и соответствует точности. Однако в вопросах типа `insufficient` модель иногда проявляет чрезмерную уверенность (> 0.70), если опирается на правдоподобный пересказ участника инцидента.

### 7. В каких случаях p-adic структура помогает, а в каких мешает?
- **Помогает:** При анализе противоречий, проверке правил с исключениями и фильтрации слухов от аппаратных логов. Структуризация группирует факты одинаковой эпистемической надежности рядом.
- **Мешает / нейтральна:** При простых прямых вопросах (типа «Во сколько произошел деплой?»), где достаточно одного совпадения по ключевым словам и дополнительная кластеризация лишь незначительно усложняет промпт.
